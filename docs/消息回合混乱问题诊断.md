# 消息回合混乱问题诊断

## 根因与复现

旧版渲染器以全局 `nodes.answer` 保存回答节点。Turn A 完成事件漏到、被过滤或请求被拒绝时，该引用不会可靠清理；Turn B 的 `answer_delta` 因此继续写入 Turn A。思考节点也仅以 `reason-<turn>` 定位，工具前后多轮推理会被合并。

最小复现：依次发送 A 的 `answer_delta("回答 A")`、B 的 `answer_delta("回答 B")`；旧代码只创建一个回答节点，内容为“回答 A回答 B”。

## 修复

Renderer 现在维护 `Map<turn_id, TurnState>`。每个 Turn 有独立文章容器、时间线、`answerNodes(round)`、`reasoningNodes(round)` 与 `toolNodes(tool_call_id)`；完成回合不会清空历史索引。未知回合事件只生成诊断，不会写入任何已有卡片。

前端以 `busy` 和 `activeTurnId` 阻止重入；终止事件只结束对应活跃回合。后端为每个流事件添加 `round`，并在缺失 `stream_end` 时发送 `stream_error`。
