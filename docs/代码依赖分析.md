# 代码依赖分析

## 分层方向

```text
frontend / cli -> llm、mcp
mcp -> openness、rag、xlsx、common
rag -> common
openness -> common（仅路径/配置需求时）
xlsx -> 第三方 openpyxl
```

当前正式包之间没有已发现的 Python 循环 import。`mcp.tools` 是工具注册与业务编排边界，依赖面最大；本轮未拆分其业务逻辑，以避免影响 TIA 行为。

## 已修复的路径依赖

- PLC 知识仅按 `data/rag/knowledge/catalog.json` 显式发布；`data/rag/raw/` 不参与运行时扫描，生成 XML 写入 `data/generated/rag/`。
- 项目根、数据、TIA 资源和生成目录统一在 `scdw.common.paths` 定义。
- Web 静态资源继续以 `scdw.frontend.app` 文件位置定位，不依赖启动目录。
- 根目录脚本只作兼容启动，不再被包内模块导入。

## 仍存在的环境路径

- `scdw.openness.tia_core` 默认 TIA PublicAPI 路径仍为 Windows 本机路径；可由 MCP 工具 `init_tia_project(api_dir=...)` 覆盖。
- `tests/integration/test_lad_import.py` 仍含本地测试工程目录与 CPU 订货号，属于人工 TIA 集成测试配置。

## 依赖声明

`pyproject.toml` 已补入源码直接使用的 `openai`、`openpyxl` 与 `pydantic`，并采用：

- 默认：MCP、DeepSeek/OpenAI 适配、XLSX、CLI；
- `llm`：Anthropic；
- `ui`：FastAPI、uvicorn、pywebview；
- `tia`：pythonnet；
- `dev`：pytest。

已执行 `uv lock` 更新 `uv.lock`。锁定过程仅解析依赖，不等同于已在当前解释器安装所有可选依赖。
