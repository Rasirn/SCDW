# 当前代码基线

## 已确认的运行入口

| 场景 | 兼容入口 | 正式实现 | 依赖环境 |
| --- | --- | --- | --- |
| CLI 对话 | `python main.py` | `scdw.cli.entry:main` | MCP、OpenAI 兼容 SDK、DeepSeek 环境变量 |
| MCP Server | `python mcp_server.py` | `scdw.mcp.server:main` | MCP、TIA Portal/Openness（执行 TIA 工具时） |
| MCP Client 调试 | `python mcp_client.py` | `scdw.mcp.client:main` | MCP Server 与 MCP Python 包 |
| Web 服务 | `uv run uvicorn scdw.frontend.app:app --app-dir src` | `scdw.frontend.app` | UI 可选依赖、DeepSeek、MCP |
| 桌面窗口 | `uv run scdw-gui` | `scdw.frontend.main_gui:main` | Web 服务依赖及 pywebview |

所有根目录入口均只负责将 `src/` 加入导入路径并调用正式实现，不包含业务逻辑。

## 已确认调用链

```text
CLI / FastAPI-WebSocket / PyWebView
  -> scdw.cli 或 scdw.frontend
  -> scdw.llm.deepseek + scdw.mcp.client
  -> scdw.mcp.server + scdw.mcp.tools
  -> scdw.openness / scdw.xlsx / scdw.rag
  -> TIA Portal Openness、data/rag、data/xlsx、data/generated
```

## 业务入口对应

- 大模型调用：`scdw.llm.deepseek.Deepseek`；Claude 封装保留于 `scdw.llm.claude`，当前默认流程未使用。
- TIA 会话创建：MCP 工具 `init_tia_project`，实现位于 `scdw.mcp.tools`。
- XLSX 解析：`scdw.xlsx.reader.read_plc_project_xlsx`。
- RAG 检索：`scdw.rag.retriever.TemplateLibrary` 与 `search_templates`。
- LAD XML 导入：MCP 工具 `import_lad_xml`，底层为 `scdw.openness.tia_blocks.import_lad_xml_block`。
- 编译检查：MCP 工具 `compile_check`，底层为 `scdw.openness.tia_compiler.compile_plc`。

## 当前无法确认或未验证的流程

- 无 TIA Portal V17、pythonnet 与 Openness 授权时，不能验证工程创建、XML 导入、硬件配置和编译。
- `scdw.mcp.client` 的 prompts/resources 方法仍是历史占位实现；CLI 相关补全功能依赖这些接口时尚未形成可验证闭环。
- 多份 `.ap17` 工程均未由 Python 代码硬编码引用，不能据此判断唯一“正式工程”。

## Phase 2–3 补充基线

- pytest 配置、TIA fixture、真实 TIA 集成测试位于 `tests/conftest.py` 与 `tests/integration/tia/`。
- 临时测试工程统一写入 `data/generated/test_projects/`；RAG 生成 XML 仍写入 `data/generated/rag/`。
- MCP 的工具调度已移至 `scdw.mcp.tool_manager`；TIA 会话改由 `scdw.openness.session.TiaSessionManager` 集中管理。
- 完整测试结果与 XML 结果分别见 `docs/Phase2测试基线报告.md`、`docs/XML导入编译基线.md`。
