# 开发指南

## 本地安装与测试

```powershell
uv sync --extra dev
uv run python -m unittest discover -s tests/unit -v
```

需要 UI 时追加 `--extra ui`；需要 TIA Openness 时追加 `--extra tia`。未安装 TIA Portal 的机器可以开发和验证路径、RAG、XLSX 与纯 Python 逻辑，但不能运行 `tests/integration/test_lad_import.py`。

## 添加 MCP 工具

在 `src/scdw/mcp/tools.py` 的 `register_mcp_tools` 中注册工具。工具应把具体 TIA 调用放在 `scdw.openness`，知识目录读取放在 `scdw.rag`，表格解析放在 `scdw.xlsx`；不要把文件路径或 XML 资源写死在工具函数中。

## 添加 Openness 操作

在 `src/scdw/openness/` 新增职责明确的模块，并由 `__init__.py` 导出公共接口。涉及真实设备、工程或下载的行为必须补充 TIA 集成测试或手工验证记录。

## 添加 PLC 知识项

1. 将 TIA V17 原始导出放入 `data/rag/raw/application/`，只作为离线证据。
2. 人工精简为 `data/rag/knowledge/` 下的 XML 片段或规则文档，保持 Parts/Wires、调用参数、局部变量 Interface 等必要上下文。
3. 在单一 `catalog.json` 中增加能力 metadata 和 `contains` 声明，并在 `distillation.json` 记录原始来源；不要添加关键词或 score。
4. 运行 `python -m pytest tests/unit/test_plc_knowledge.py -q`。只有完整可导入样本才需要额外执行 TIA 导入/编译验证。

## 路径、数据和文档规范

- 使用 `scdw.common.paths`；不得以当前工作目录推导数据位置。
- 人工维护资源写入 `data/`，运行产物写入 `data/generated/`。
- 新增代码 docstring、注释、CLI 提示和文档使用中文；第三方 API、TIA 固定名称与 XML 标签保持原文。
- 不确定的历史资产先归档到 `archive/` 并更新 `docs/项目资产清单.md`。

## pytest 回归命令

```powershell
python -m pytest tests/unit -m unit -q
python -m pytest tests/integration/tia -m tia -vv --timeout=55
python -m pytest -m "not requires_model"
```

TIA 测试、统一异常和结果类型说明见 `docs/TIA测试指南.md`、`scdw.common.exceptions` 与 `scdw.common.result`。
# 已打开 TIA 调试

先在 TIA Portal 中打开测试工程，再执行 `scripts/diagnose_tia_attach.py --process-id <PID>`。首次连接需要确认 Openness 授权。请勿用正式工程做导入、编译回归。
