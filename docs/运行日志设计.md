# MACtrl 运行日志设计

每次 GUI 启动都会创建 `data/logs/YYYYMMDD_HHMMSS_mmm_<六码>/`。启动进程把 `MACTRL_RUN_ID`、`MACTRL_RUN_DIR`、`MACTRL_PARENT_PID` 传给 MCP 子进程，因此 Web、LLM、MCP 和 TIA 记录属于同一次运行。

目录中的 `manifest.json` 保存运行环境与版本；`session.jsonl` 是完整事件时间线；`runtime.log` 便于直接阅读；`conversation.md` 记录回合摘要；`payloads/` 保存超过 4000 字符的请求或响应；`mcp/mcp.jsonl` 保存 MCP 侧事件；`tia/tia_operations.jsonl` 保存 TIA 调用边界；`crash/` 预留给崩溃转储。

每条 JSONL 都有 `sequence`、本地与 UTC 时间、`elapsed_ms`、进程和线程信息，并在可用时携带 `run_id`、`conversation_id`、`turn_id`、`round`、`tool_call_id`、`operation_id`。长载荷在主记录中仅保留路径、SHA-256、长度及预览；API Key、Token、密码和类似 `sk-...` 的字符串会脱敏。

排障时先按运行目录定位，再用 `conversation_id → turn_id → round → tool_call_id` 关联：`turn_started` 确认请求到达，`deepseek_stream_*` 确认模型调用，`mcp_tool_call_*` 确认工具边界，`tia_*` 确认 PID、项目上下文和执行线程。MCP 的协议 stdout 不写运行日志，文件日志避免污染 stdio 协议。
